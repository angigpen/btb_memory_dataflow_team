# Set 5 — Set 4 기반 읽기 순서 3안 × ACC 2/4세트

GitHub의 Set 4 커밋은 SOURCE.txt에 기록했습니다. 폴더마다 독립적인 RTL 여섯 파일이 들어 있습니다. 사용할 폴더 하나의 파일만 프로젝트에 추가하세요. 서로 다른 폴더의 같은 이름 모듈을 동시에 추가하면 중복 정의됩니다.

| 폴더 | ACC | 읽기 순서 |
|---|---:|---|
| plan1_acc2 | 2 | 같은 k의 B 4개 → ACC 2세트의 A 각 4개 |
| plan1_acc4 | 4 | 같은 k의 B 4개 → ACC 4세트의 A 각 4개 |
| plan2_acc2 | 2 | B 4×4를 가로 우선 → k마다 ACC 2세트의 A |
| plan2_acc4 | 4 | B 4×4를 가로 우선 → k마다 ACC 4세트의 A |
| plan3_acc2 | 2 | B 4×4를 세로 우선 → k마다 ACC 2세트의 A |
| plan3_acc4 | 4 | B 4×4를 세로 우선 → k마다 ACC 4세트의 A |

B k=0 “하나”는 INT8 한 바이트가 아니라 같은 k의 가로 4개짜리 패킷 하나로 해석했습니다. 외부 메모리는 기존처럼 한 요청에 INT8 한 개, outstanding 1개입니다. B 세로 읽기는 주소에 N을 더하는 scalar 요청입니다.

## 첫 블록 읽기 순서

행렬 B의 열 수가 N일 때, 출력 열 타일 0, k=0부터 다음과 같이 요청합니다.

- 1안: B[0,0..3], A[0..4×ACC-1,0], B[1,0..3], A[0..4×ACC-1,1], …
- 2안: B[0,0..3], B[1,0..3], B[2,0..3], B[3,0..3], 이어 A[0..4×ACC-1,0], A[0..4×ACC-1,1], …
- 3안: B[0..3,0], B[0..3,1], B[0..3,2], B[0..3,3], 이어 A는 2안과 같은 순서.

K나 N의 끝이 네 개 미만이면 실제 유효 원소만 읽습니다.

## 기존 Set 4 구조

A/B reuse RAM 용량, 4개 packet slots와 supply 구조, B share, 결과 FIFO, compute 및 sparsity 인터페이스를 유지했습니다. A/B가 RAM hit이면 외부 read는 발생하지 않으며 기존처럼 RAM에서 가져옵니다. 따라서 위 순서는 새 데이터를 외부에서 가져와야 하는 경우의 순서입니다.

- A RAM은 기본 4096×32 bit = 16 KiB입니다.
- B RAM은 기본 1024×32 bit = 4 KiB입니다.
- NSLOTS=4이며 기존 네 개의 operand packet slots를 유지합니다.
- ACC는 2세트 128 B, 4세트 256 B의 INT32 데이터입니다.
- 1안은 loader의 B lane 우선순위만 변경했습니다.
- 2/3안은 기존 loader와 메모리 사이에 B 모으기 경로를 추가했습니다. 최대 16 B를 보관하고 기존 loader의 byte 요청에 응답합니다. 기존 B reuse RAM은 원래 fill/hit 정책으로 계속 동작합니다. 16 B 외에 주소와 상태용 제어 레지스터가 추가됩니다.
- 2/3안의 b_prefetch_bridge 모듈은 operand_loader.v 마지막에 들어 있습니다. 별도의 일곱 번째 파일을 추가할 필요가 없습니다.
- 기존 controller의 k → bank 순서와 op_first/op_last 및 op_bank의 의미를 유지했습니다. N:M 연산기와 새로운 압축 인터페이스 구현은 포함하지 않았습니다.

2/3안에서는 B를 16개 먼저 받아도 기존 sparsity 입력에는 원래대로 A+B 패킷이 전달됩니다. B N:4 판정이 빨리 시작되려면 B 사전 분석 입력이나 그룹 인터페이스가 추가로 필요합니다. 이번 RTL은 세 가지 외부 읽기 순서를 검증하는 구현입니다.

한 포트를 통해 모으는 과정과 byte 응답을 중계하는 단계 때문에 2/3안의 사이클이 줄어든다고 보장하지 않습니다. 결과는 results.csv에서 비교하세요. FPGA 합성 자원·Fmax·전력은 아직 측정하지 않았습니다.

## 검증 실행

Python 3와 Icarus Verilog의 iverilog, vvp가 PATH에 있으면 다음을 실행합니다.

    python3 run_tests.py

tests/에는 공식 testbench와 입력 생성기를 포함했습니다. 여섯 RTL을 각각 컴파일해 C 정답, valid/ready 안정성, reset/restart, 임의 stall, 끝 타일, K=1024, 작은 버퍼에서 그룹 전환 및 A 용량 초과를 검사합니다. A20×6, B6×12 예제는 외부에서 실제 수락된 모든 메모리 요청을 reads.csv에 기록하고 요청한 순서와 대조합니다.

기본 검증은 각 안당 43개 케이스입니다. 전체 최대 크기 64×128×1024를 추가하려면 --max-dimensions 옵션을 사용합니다.

build/에 실행 로그와 입력 및 metrics.csv가 생성됩니다. 최상위 results.csv는 여섯 안의 결과를 합친 표입니다. 이 폴더는 기존 Set 4와 별도입니다.
