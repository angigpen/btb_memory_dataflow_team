Additional on-chip memory (default parameters, from the RTL declarations)

Counted: data storage on the operand path — packet registers/slots, request tracking, tag FIFO, A cache, B buffer (bit widths taken from the reg/sdp_ram declarations and each set's gemm_top.v defaults; PE 4×4). Not counted: FSM/address/counter registers that baseline also has. BRAM36 = Xilinx block RAM count by aspect ratio (1K×36, 4K×9, …; BRAM18 = 0.5); Vivado may map small RAMs to LUTRAM instead. Yosys estimate in the README: Set 1 ≈ 1 BRAM36 / +100 FF, Set 2 ≈ 5 BRAM36 / +300 FF.

Set 3 B-buffer sweep — 64×128×128 (from results/set3_results.csv)

Where Set 3 matters: B for 64×128×128 is 16 KB. With the same 4 KB buffer, Set 2 can only reuse the column tiles that fit; Set 3 reorders the loop (group → row tile → col tile in group → kk) so the buffer is refilled per group and every byte of B is read once.
